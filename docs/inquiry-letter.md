我们正评估将贵司星形自组网图数遥模组用于**民用无人机 / 移动机器人**场景（双向遥控、遥测与视频回传；业务目标先验证 **1 中心 + 4 终端**，再扩展至 **1 + 16**）。公开宣传页信息不足以完成立项评审，现按决策优先级恳请提供下列**书面资料**（电子版即可）。若某项涉密或需 NDA，请告知签署流程与可替代摘要口径。

## 一、完整规格与接口文件（最高优先）

请提供与**拟报价 / 拟出货型号**一致的规格与接口说明（非宣传册摘要），至少包括：

1. **准确型号、硬件版本、固件 / WLS Manager（或配套软件）版本号**  
2. **工作频段与信道表**（含各区域可配选项；若界面出现 1.4 GHz 等选项，请标明在中国大陆是否允许双向业务使用及适用核准文号）  
3. **供电**：电压范围、典型 / 峰值功耗、上电时序、反接与浪涌要求  
4. **全部对外接口的电气与机械定义**：  
   - ETH1 / ETH2：速率、是否二层桥、VLAN、巨帧、LED 含义  
   - UART1 / UART2：电平（TTL/RS232）、波特率范围、流控、针脚  
   - **SBUS**：方向（输入/输出/可配）、电平与反相、帧格式确认、与飞控对接注意点  
5. **天线接口**：阻抗、推荐增益、馈线损耗预算假设、是否支持 MIMO / 分集  
6. **环境与结构**：工作温度、防护等级、安装约束、散热要求  

若有**接口针脚图 / 原理图级连接说明 / 快速上手接线清单**，请一并提供。

---

## 二、带测试条件的性能报告

请提供可复核的测试报告或原始记录摘要，**每一项请写明测试条件**（否则无法用于需求冻结）：

| 指标 | 请写明的条件（示例） |
|---|---|
| 通信距离（如 12 km） | 频段、带宽/MCS、天线型号与架高、地形/视距、业务负载（是否含视频）、方向（空对地/地对地）、RSSI/BLER/吞吐随距离曲线 |
| 网络时延（如 ≤15 ms） | **测量起止点**（模组入口→出口？）、单向还是往返、包长、发送频率、背景负载、节点数（2 节点还是多节点）、统计量（平均/P99） |
| 应用有效吞吐 | 用 iperf3 或等价方法测得的**有效载荷**速率；上下行分别给出；距离与 MCS；**不要用网口协商速率代替** |
| 视频相关 | 若宣传含图传：编码格式/码率、分辨率、端到端还是空口段、丢包与卡顿记录 |

说明：我们理解「≤15 ms」通常指模组入口到出口的链路时延，**不能**直接当作摄像头到显示的端到端时延；请在报告中避免口径混用，或明确区分。

---

## 三、多节点与业务调度说明（决定能否 1 带 16）

星形「最多 16 终端」是拓扑上限；我们需要确认**并发业务**能力。请书面说明或提供测试数据：

1. **1 中心 + 4 / 8 / 16 终端**同时在线时的：  
   - 总**应用有效**容量（上下行分配）  
   - **单终端保底带宽**（满载时逐台，而非平均值）  
2. **内部是否支持业务优先级**（例如遥控 > 数传 > 图传）？若支持，外部如何配置？若不支持，拥塞时控制面行为是什么？  
3. **弱链路 / 远距离终端**是否会占用过多空口资源并抬高其他终端的控制时延？有无隔离或公平策略？  
4. **视频业务典型模式**：是否必须「全员低码率 + 点名主码流」？主视频源切换时，其他终端遥控是否保证不中断？  
5. **中心节点故障**后：终端行为、是否有接管 / 降级、恢复时间  
6. 节点**加入 / 掉线 / 重连 / 目的节点隔离**的流程与超时参数  

若可提供「视频满载注入下控制包时延分布」的实验室曲线，将极大加快我们的拥塞与 QoS 验收设计。

## 四、安全、管理与合规资料

1. **入网鉴权 / 加密**：机制概述、密钥管理、是否支持白名单、防重放；导出管制与国内使用注意点  
2. **状态与运维**：链路质量、节点列表、RSSI/SNR/MCS、掉线原因等**可读接口**（SDK / API / 串口命令 / 网管）  
3. **升级与回滚**：固件升级路径、失败回滚、版本兼容矩阵  
4. **合规**：拟供货型号适用的无线电核准、销售区域限制；针对**中国大陆无人机 / 机器人**项目，请明示推荐频段与不可用频段
